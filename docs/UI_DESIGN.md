# Running Art — 介面與造型設定

這份文件講的是**看得到的東西怎麼被畫出來**：配色、跑者圖示、方向箭頭、
高程折線圖、匯出圖片的版面。演算法的部分在 `ARCHITECTURE.md`。

全部都在 `deploy/index.html` 這一個檔案裡（`web_prototype/ui_prototype.html` 是同一份）。

## 一、配色系統

### 唯一來源是 CSS 變數

所有顏色定義在檔頭的 `:root`（深色）與 `body.light`（淺色）兩個區塊，
變數一律以 `--rt-` 開頭。**JS 不自己寫死顏色**，而是透過 `PC()` 讀出來：

```js
const P = PC();          // 回傳 {done, pending, arrow, runner, ...}
ctx.strokeStyle = P.done;
```

`PC()` 會快取 `getComputedStyle` 的結果，`setTheme()` 裡呼叫 `palInvalidate()` 讓它失效。
**要換配色只改那兩個 CSS 區塊**，Canvas、Leaflet 圖層、UI 按鈕會一起跟著變。

> 這個設計是為了修一個實際發生過的 bug：地圖上的箭頭是青色、匯出的 PNG 卻是金色，
> 因為同一個「箭頭顏色」在 CSS 和 JS 各寫了一份，改了一邊忘了另一邊。

### 目前的配色：電光 · 青檸

| 變數 | 深色 | 淺色 | 用途 |
|---|---|---|---|
| `--rt-done` | `#B8FF3C` | `#4D7C0F` | 已跑過的路線 |
| `--rt-pending` | `#6E7A88` | `#B6C0CB` | 還沒跑到的路線 |
| `--rt-connector` | `#FFFFFF` | `#8A94A0` | 連接段虛線 |
| `--rt-draw` | `#E8EEF4` | `#1A2029` | 正在畫的手繪線（要顯眼） |
| `--rt-guide` | `#59636F` | `#586470` | 產生路線後透出來的手繪線（要退到背景） |
| `--rt-arrow` | `#FFFFFF` | `#FFFFFF` | 方向箭頭（**靠陰影襯出來**，見第三章） |
| `--rt-runner` / `--rt-runner-out` | `#FFFFFF` / `#10151A` | `#FFFFFF` / `#10151A` | 小人本體／外框（白底黑框，兩個主題相同） |

| `--rt-node` / `--rt-node-turn` / `--rt-node-sel` | `#8A94A0` / `#FFFFFF` / `#FF4D5E` | `#6B7684` / `#1F2937` / `#E11D48` | 微調模式的節點 |
| `--rt-ui` / `--rt-ui-text` | `#B8FF3C` / `#111806` | `#4D7C0F` / `#FFFFFF` | 介面主色／其上的文字 |
| `--rt-ui-ink` | `#B8FF3C` | `#3C6109` | 疊在「主色淡底」上的文字 |
| `--rt-on-accent` | `#10151A` | `#FFFFFF` | 疊在強調色填色上的圖形（圖釘符號、外框） |

### 三個設計原則

1. **進度用明度階，不用色相。** 已跑／未跑是同一個色系的亮暗兩階，
   不是兩個不相干的顏色——這是整組看起來乾淨的主因。
2. **只有一個高彩度色**，留給「當下位置」相關的東西（小人、箭頭、終點）。
3. **淺色不是把深色反過來。** 近白的路線在淺色地圖上會直接消失，
   所以明度階整個翻面（已跑變深、未跑變淺）。

### 為什麼會有 `--rt-ui-ink`

匯出對話框的多選鈕用「色框 + 16% 淡底」的樣式（一排實心亮色在深色模式下太刺眼）。
深色時主色本身當文字沒問題，**淺色時只有 4.05:1**（底是它自己的淡色），
所以另外給一個壓深一階的值。

### 量測過的兩個數字

- **未跑路線 `#6E7A88`**：提亮後的 CARTO 深色圖磚，街道亮度 p85≈43、地塊 p35≈28。
  原本的 `#374049` 對街道只有 **1.34:1**，會融進地圖；現在是 **3.24:1**。
- **手繪線（淺色）`#586470`**：原本 `#98A2AE` 對未跑線只有 **1.40:1**，兩條線看起來一樣。

### 主題切換要手動重染

Leaflet 圖層和 divIcon 的顏色是**建立當下就寫死的**，不會跟著 CSS 變數走。
所以 `setTheme()` 尾端要一個一個重建：

```js
palInvalidate();
applyResult(S.result,false);   // 路線 polyline
refreshSEMarkers();            // 起訖點圖釘
pvRestyleArrows();             // 方向箭頭 divIcon
renderElevChart(elevChartData);
if(S.editing) editBuild();     // 微調節點
```

## 二、跑者小人

採用「粗壯」比例。**幾何只寫一份**（`RUNNER` 常數 + `runnerParts()`），
地圖的 SVG 圖示和匯出的 Canvas 都從這裡長出來，不會分岔。

### 五段，沒有脖子

| 部位 | 線寬 | 端點 |
|---|---|---|
| 軀幹 | 6.4u | **butt** |
| 手臂 ×2 | 3.0u | round |
| 腿 ×2 | 2.8u | round |
| 頭 | 半徑 3.2u 的實心圓 | — |

沒有脖子那一段：**圓頭 → 空隙（`headGap` 1.8u）→ 平的軀幹頂**。

### ⚠️ 軀幹一定要用 `butt` 端點

`lineCap:'round'` 的圓端會往外凸出半個線寬。軀幹 6.4u 寬 → 凸出 3.2u，
會把頭下方的空隙整個填滿，頭和身體黏成一塊。

### 肩膀

手臂接在軀幹頂面附近的肩膀支點 `(±2.6u, torsoTop + 1.3u)`，
**兩種姿勢共用同一個支點**——跑步舉手就是繞著它轉，不會有手臂憑空長在腰上的感覺。

手臂用 round cap，端點是半圓，所以肩膀是圓的、不會出現尖角。
`shoulderDrop` 要夠深（1.3u）：圓端會往上凸 1.5u，太淺的話會伸進頭下方的空隙裡
把「沒有脖子」的縫隙填掉。

跑步舉手時**加長要沿著原本的斜率往外延伸**（約 −0.8），不要靠加大 `armHandRiseRun`——
舉太高手臂會撞到頭。目前手臂長 5.47u（`armHandXRun` 6.8、`armHandRiseRun` 3.5），
實測放大檢視時頭正下方的空白帶：立正 16px、跑步 12px，都沒有碰到頭。

立正時 `armHandXStand` 是 4.2u，手臂外緣落在 5.7u、露出軀幹外 **2.5u**。
原本 2.8u 只露出 1.10u，遠看像沒有手臂。

### 兩腿

`legX ± legW/2` 的外緣正好是 ±3.2u ＝ 軀幹半寬，
中間縫隙 `2×legX − legW` = **0.8u**（原本 1.4u，依需求縮小）。

- **立正**：兩腿垂直併攏。
- **跑步**：腿張開到 ±3.8u。

### 兩種姿勢

`drawRunnerCanvas(ctx,x,footY,u,light,active)` 與 `personSVG(active)`：

- **`active`（拖曳／播放中）＝ 跑步**：繞肩膀舉手、腿張開。
- **靜止 ＝ 立正**：手貼身側幾乎垂直、兩腿垂直併攏。

匯出圖固定畫立正——靜態圖沒有動作可以表現。

### 尺寸

地圖圖示 `viewBox "0 0 30 34"`、`iconAnchor [19.5,39]`（腳底對齊定位點），
渲染尺寸 39×44 ＝ viewBox 的 1.3 倍，所以 **geometry 不用改就等於整個人放大 30%**。
匯出時 `u = 1.69 × sc`（同樣是 1.3 × 1.3）。
實際只有 30px 出頭高，1u 不到 1.3px——所以細節（頭身空隙、腿縫）在真實尺寸下
只剩 1～2px，改比例時一定要在真實尺寸下確認，不能只看放大圖。

## 二之二、Logo

使用者自己設計的兩個檔案，放在 `deploy/` 根目錄：

| 檔案 | 底色 | 主色 | 次色 |
|---|---|---|---|
| `logo_dark.svg` | `#14171C` | `#B8FF3C` | `#6E7A88` |
| `logo_bright.svg` | `white` | `#4D7C0F` | `#B6C0CB` |

兩個都是 `viewBox 0 0 247 247` 的**圓角方塊圖磚**（自帶底色，不是去背的標誌），
用的正好是本專案的配色，所以和介面天然一致。
內含兩張 base64 PNG（`<defs><image>` + `<use>`），其餘是向量。
**更新 logo 時把新檔覆蓋到 `deploy/` 和 `web_prototype/` 即可**，程式不用改。

### 用在哪三個地方

1. **左上角品牌**：`<img id="brandLogo">`，`setTheme()` 依主題換 `src`。
2. **Favicon**：`<link rel="icon" href="logo_dark.svg">`。深色圖磚自帶底色，
   在淺色和深色的分頁列上都看得清楚，所以不用做兩套。
3. **匯出圖片**：畫在**地圖區右下角**，邊距 `26u`（和比例尺同一個值），尺寸 `84u`。
   比例尺在左下、最寬到 `mapW*0.3`，實測兩者最近仍有 681px，不會撞到。

### ⚠️ 載入時要先補上尺寸

這兩個檔案的 `<svg>` 是 `width="100%" height="100%"`。當成 `<img>` 載入時
**沒有明確的內在尺寸**，某些瀏覽器會算成 0 而畫不出來。

所以 `loadLogoBitmap()` 會先 `fetch` 文字、把百分比換成 viewBox 的實際尺寸，
再包成 blob → `createImageBitmap`。走 blob 還有第二個好處：
blob 是同源的，**畫進 canvas 不會污染它**（和圖磚同一套安全路徑）。
實測匯出後 `canvasIsTainted()` 為 false、`toBlob()` 正常。

### 文字浮水印的取捨

地圖區有 logo 之後，原本「沒有資訊欄時把 RUNNING ART 畫在地圖右下角」那段
會和 logo 疊在一起，所以改成**只有在 logo 也關掉時**才畫。
資訊欄裡的 RUNNING ART 文字仍然保留（不同區塊，不衝突）。

## 三、方向箭頭

### 幾何只寫一份

`ARROW_STYLES` 用正規化座標（指向 +X、大約落在 ±1 內）定義形狀，
地圖的 SVG divIcon 和匯出的 Canvas **都從這一份長出來**。

```js
chevron:{ shapes:[{pts:[[-0.70,-0.70],[0.70,0],[-0.70,0.70]],
                   closed:false, mode:'stroke', w:0.42}] }
```

五種造型：`chevron` 單箭頭、`double` 雙箭頭、`triangle` 實心三角、
`dart` 後掠飛鏢（**目前的預設**）、`streak` 速度尾線。

### 轉角是真的幾何倒角

`arrowGeom(shape, r)` 把每個折點換成一段**二次貝茲**，回傳 `M/L/Q/Z` 指令，
Canvas 和 SVG 共用同一份結果。

> 為什麼不用 `lineJoin:'round'`：它的圓角半徑等於線寬的一半、**改不動**，
> 尖端一定是鈍的。用幾何倒角才能把半徑調小到「有點銳利但不衝擊」。

半徑存在 `arrowRadius`（預設 `0.10`，正規化單位；小 = 銳利）。
用倒角之後 `lineJoin` 要設 `miter`，否則轉角會被圓兩次。

### ⚠️ 箭頭是白色，靠陰影才看得見

兩個主題的箭頭都是白色。深色模式沒問題，但**淺色模式下白箭頭疊在未跑路線
`#B6C0CB` 上只有 1.84:1、疊在地圖底上只有 1.19:1**——完全靠陰影襯出輪廓。

所以陰影在**兩個地方都必須有**，缺一邊那邊就會看不見。
強度分主題（`ARROW_SHADOW`），淺色要深很多：

| | 地圖（SVG filter） | 匯出（Canvas） |
|---|---|---|
| 深色 | `drop-shadow(0 0 1.6px rgba(0,0,0,.7))` | `.70` / blur `base*0.60` / **1 次** |
| 淺色 | 兩層 `drop-shadow`：`1.4px .85` + `2.6px .6` | `.85` / blur `base*0.75` / **2 次** |

匯出那邊原本**完全沒有陰影**（`shadowBlur` 出現次數 0），是改白色時才補上的。

強度是量出來的。在 12px 的匯出箭頭上，未跑路線底色亮度 192，陰影讓周圍最暗降到：

| 設定 | 最暗 | 比底色暗 45 以上的像素 |
|---|---|---|
| `.55` / 0.42 / 1 次 | — | 0 |
| `.70` / 0.60 / 1 次 | 150 | 0 |
| **`.85` / 0.75 / 2 次** | **98** | **28** |

⚠️ **「畫兩次」才是加深的關鍵**：只畫一次的話，alpha 調到 `1.0` 也只到 132——
單次繪製的陰影衰減有上限，疊第二次才會真的變深。

`drawChevron()` 因此分成兩段：**先跑 `passes` 次帶陰影的繪製**、
**再清掉陰影補描邊**——否則補的那圈描邊會再疊一層陰影，把箭頭壓暗。

同理小人也是白本體：它對淺色地圖只有 1.19:1，靠的是那圈加粗 2.4u 的
深色外框（15.47:1）撐出輪廓。

### 尺寸

地圖上約 26px、匯出的 1080px 圖上約 **12px**。
造型細節在 12px 大多會塌掉，所以挑造型時要看實際大小而不是放大圖。

## 四、高程折線圖（同時是路線預覽的拉桿）

### 它就是拉桿

高程圖和路線預覽本來就共用同一個進度值和同一條「距離」橫軸，所以合併成一個控制項：
**在圖上拖曳 = 拉時間軸**。獨立的 `<input type="range">` 已經移除，
進度存在 `S.pvFrac`。

- `#elevChartArea` 一定要有 `touch-action:none`，否則手機上在圖上拖曳
  會被當成捲動結果面板。
- 鍵盤（方向鍵／Home／End）和 `role="slider"` + `aria-valuenow` 是手動補的，
  換成自訂控制項後不會自動獲得。

### 座標系

```js
const EL_W=340, EL_H=92, EL_PADT=28, EL_PADB=28,
      EL_LBL_GAP=15, EL_LBL_EDGE=10;
```

SVG 是 `preserveAspectRatio="none"` 拉伸的（實測橫向被拉 2 倍），所以：

- **高低點與標籤不畫在 SVG 裡**，改用百分比定位的 HTML 疊層。
  畫在 SVG 裡的話 `<circle>` 會變扁橢圓、文字被拉寬。
- 折線加 `vector-effect="non-scaling-stroke"`，線寬才不會被拉伸。
- `updateElevRunnerDot()` 必須用**和 renderElevChart 完全相同**的常數，
  用容器的 `offsetHeight` 會固定偏差約 1px。

`EL_LBL_GAP`（標籤離點多遠）和 `EL_LBL_EDGE`（標籤最少離邊界多遠）要分開，
共用一個值的話「離點遠一點」會被「不要超出邊界」夾回來。

### 已跑／未跑

用一個 `clipPath` 切開：整條先用 `--rt-elev-dim` 畫，再把
`<g clip-path>` 裡的亮色版本切到進度位置。拖曳時**只改那個 rect 的寬度**，
不重建整段 SVG。

### 標籤沒有底色

最高固定在點的上方、最低固定在下方，用**同底色的細描邊**（`text-shadow` / `strokeText`）
把字襯出來，不加底色方塊——方塊會蓋住底下的折線。
實測：折線佔 389 欄，標籤現在吃掉 0 欄。

## 五、匯出圖片的版面

### 三塊

```
┌─────────────────────────┐
│  地圖區                  │  路線 + 箭頭 + 起訖點 + 小人
│  （最多再加比例尺）        │  ← 其他東西都不放這裡
├─────────────────────────┤
│  地點 · 日期   PLACE_ROW_H = 95   │
├─────────────────────────┤
│  數據 cells   STATS_ROW_H = 155  │
├─────────────────────────┤
│  高程圖 + 浮水印  ELEV_BAND_H = 230 │
└─────────────────────────┘
```

每一塊都可以獨立關掉，**關掉就不佔高度**（不會留空白）。
所以各列的位置要用**絕對位移**算，不能用「總高的比例」——
用比例的話關掉一列會讓其他列跑掉。

解析度固定寬 1080：`1:1` 1080×1080、`4:5` 1080×1350、`9:16` 1080×1920。

### 預覽和成品共用同一份程式

`drawInfoPanel()` 和 `drawScaleBar()` 由匯出和對話框預覽**同時呼叫**，
差別只有一個縮放係數 `sc`。所以預覽看到的排版、字級比例、每個東西的位置
就是成品的樣子（實測資訊欄佔比誤差在 0.3 個百分點內）。

> 以前預覽只畫幾個灰色方塊示意、而且自己有一組簡化的顏色，和成品對不起來。

### 數據欄位是按內容分配寬度

不是平均切。平均切的話五項全開時每欄只有 201px，而「↑142 ↓138 m」就要 240px，
於是它被縮到很小、又幾乎頂到隔壁欄。
現在先量出每欄需要的寬度才排版，長的欄多佔一點，並且**所有欄位共用同一個字級**。
項目越多字級起點越低（5 項 38px / 4 項 42px / 其餘 46px），
多出來的空間變成欄距。

### 圖磚與 CORS

匯出用的地圖圖磚一律走 `fetch → Blob → createImageBitmap`。
blob 是同源資料，畫進 canvas **永遠不會污染它**，所以 `toBlob()` 不會丟 SecurityError。
備援是 `<img crossOrigin>`；兩條都失敗就那一格留底色。
**刻意不退回「不設 crossOrigin 的 img」**——那雖然畫得出來，但會毀掉整張圖的匯出。

匯出前還會用 `getImageData` 主動偵測污染，髒了就自動改用無底圖版本重畫並告知原因。

`ctx.filter` 在舊版 Safari 沒有實作，所以深色圖磚的提亮有備援：
用 `'lighter'` 加法疊圖模擬 `brightness(k)`（數學上等價）。

## 六、下載為什麼要跳出結果對話框

**不能在 `await` 之後直接 `a.click()`**：Safari／iOS 會判定已經離開使用者手勢，
把下載當成彈窗靜默擋掉。

所以產生完成後跳出 `#pngResult`，由使用者按「儲存圖片」——**那一下才是有效的手勢**。
有支援時多一顆「分享」（Web Share API，iOS 存進相簿的正規路徑），
手機也可以直接長按圖片。

## 七、微調路徑的互動

### 兩種操作

1. **點一下節點**＝選取（可多選、可框選），按「刪除選取」讓路線繞過它們。
2. **按住節點拖曳**＝把路徑改走附近的路口。

### 拖曳時只查「當下這個節點」附近

實測台北路網 **4670 節點/km²**。如果把整條路線 20m 內的節點全部畫出來，
5km 路線會有約 **934 個點**——而路線本身才 90 個節點就已經很擠了。
所以候選點只在按住某個節點時才去查。

**只取路口（degree ≥ 3）**：直路中間的節點只是幾何轉點，移過去不會改變走法。

半徑是漸進的：先找 20m，落空才放寬到 60m。
（實測從真實道路節點出發，**65% 在 20m 內一個路口都沒有**；60m 時中位數 4 個、不會落空。）
一次最多顯示 12 個。

### 拖曳中的路徑預覽

高亮的候選點換掉時，用 `Engine.previewMove()` 算出「放開後會變成什麼樣」畫成虛線。
這個 API **完全不改動 `SEGS`**，和真正套用的 `editMove()` 分開——
它會在拖曳中被反覆呼叫，有副作用就完蛋了。約 3ms。

### 按鈕狀態的特異性陷阱

`#editDock .sm`（特異性 1,0,1）會壓過 `.sm.on` / `.sm.danger`（0,2,0），
造成「框選」按了不變色、「刪除選取」失去紅色。
微調工具列的狀態樣式**必須寫成 `#editDock .sm.on`** 才蓋得過去。

### 節點數膠囊的位置

`updatePillPos()` 要量「目前顯示中的那個工具列」。
以前寫死量 `mainDock`，但進微調模式後它是 `hidden`、量到寬度 0 就直接 return，
膠囊停在 CSS 預設的 88px，而 `editDock` 有 108px 高，實測會壓到按鈕 32px。

## 八、深／淺主題與 i18n

- CSS `:root` / `body.light` 兩組變數，`setTheme(light)` 切 class 並存 localStorage。
- 靜態文字用 `data-en` 屬性，`applyLang()` 在 `data-zh`／`data-en` 之間切 `textContent`。
  **圖示＋文字的按鈕要把文字包在自己的 `<span>` 裡**，否則 `textContent` 會把 SVG 一起蓋掉。
- 動態文字：`toast()` 查 `TOASTS_EN`、`busy()` 查 `PROG_EN`；有插值的用 `tx(zh,en)`。

## 九、量測方法（怎麼驗證這些東西沒壞）

因為介面幾乎都是 Canvas 畫出來的，很多東西**用看的不準、要用量的**。
這個專案實際用過的做法：

- **對比度**：用 WCAG 相對亮度公式算前景／背景比值。注意 `getComputedStyle`
  可能回傳 `color(srgb 0.3 0.48 0.05 / 0.16)` 這種格式（0~1 浮點），
  而且半透明要先和祖先的不透明底色做 alpha 合成，否則算出來是錯的。
- **形狀比例**：把圖形畫到放大的 canvas 上，逐列掃描相同顏色的連續區段，
  量出各部位的寬度與縫隙。要小心圓端點會往外凸、把相鄰部位的量測污染掉。
- **版面**：逐列判斷「這一列是不是資訊欄底色」找出資訊欄的起點，比對匯出與預覽的比例。
- **顏色有沒有漏改**：匯出一張圖，數舊色碼還剩幾個像素（應為 0）。

⚠️ **瀏覽器窗格收合時，CSS transition 不會前進**，`getComputedStyle` 會卡在
切換前的值。看到「主題切了但顏色沒變」先確認是不是這個，
把 `transition` 暫時關掉再量一次就知道。
